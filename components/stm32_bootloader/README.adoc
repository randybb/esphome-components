= stm32_bootloader

Flashes an STM32 through its ROM UART bootloader (ST AN3155). The ESP drives
BOOT0 and NRST, so the target needs neither a debug probe nor USB DFU, only
the UART it already shares with the ESP (e.g. for `packet_transport`).

Between flashes the component is idle and the UART belongs to whatever else
uses it. While flashing it switches the UART to even parity (8E1, required by
the bootloader) and back afterwards.

== Configuration

[source,yaml]
----
external_components:
  - source: github://randybb/esphome-components
    components: [stm32_bootloader]

http_request:

uart:
  id: stm32_link
  tx_pin: GPIO17   # -> target RX (PA10)
  rx_pin: GPIO16   # <- target TX (PA9)
  baud_rate: 115200

stm32_bootloader:
  id: stm32
  uart_id: stm32_link
  boot0_pin: GPIO4
  reset_pin: GPIO5

button:
  - platform: template
    name: Flash STM32
    on_press:
      - lambda: id(stm32).flash("http://192.168.1.10/zephyr.signed.bin", 0x08010000);
----

[cols="1,1,3",options="header"]
|===
|Option |Default |Description
|`uart_id` |required |UART wired to a USART the bootloader listens on
|`boot0_pin` |required |BOOT0, high selects the ROM bootloader on reset
|`reset_pin` |required |NRST, driven low to reset; use `mode: output_open_drain` if the board has its own reset button or supervisor
|`http_request_id` |the only one |`http_request` component the image is downloaded with
|===

Wire GND as well. The bootloader listens on USART1 PA9/PA10 on every STM32F1/F4,
plus USART2 PA2/PA3 (F401/F411) or USART3 (F405/F407), see AN2606 for the rest.

== From lambdas

* `id(stm32).flash(url, address)` downloads a raw binary and writes it to the
target's flash at `address` (default `0x08000000`), then resets the target into
its firmware. It blocks until done, like HTTP OTA. Returns `false` on failure.
* `id(stm32).reset_target()` pulses NRST with BOOT0 low.

== Flashing

* Supported are the STM32F1 (bank 1) and STM32F4 (first 1 MB) families,
detected from the bootloader's product ID. The bootloader's own Get command
decides between Erase and Extended Erase.
* `address` must start a flash page (F1) or sector (F4). The pages/sectors are
erased as the image arrives, the rest of the flash is left alone.
* Every 256 byte chunk is read back and compared.
* If the download fails halfway, the target is left with a partial image in
the bootloader. Run `flash()` again; BOOT0 is released and the target reset
either way.
* Readout or write protection is not lifted, the write then fails with NACK.

For a target on the zephyr fork with MCUboot, flash the signed application
image to the start of `slot0_partition`, not the whole flash. MCUboot itself
only has to be flashed once (DFU, ST-LINK or `flash()` to `0x08000000`).

At 115200 Bd a 100 kB image takes about 20 s (write and read back).

== Notes

* The Black Pill pulls BOOT0 down through 10 kΩ next to its button, the ESP
pin drives it high without removing anything.
* The bootloader detects the baud rate from the first `0x7F`, any rate up to
115200 works without changing the target.
