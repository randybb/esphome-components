= can_tools

CAN bus tools on top of any `canbus` platform (`esp32_can`, `mcp2515`, ...).

* Diagnostic requests (OBD-II, UDS, manufacturer services like Toyota's `0x21`): sent as an
  ISO-TP single frame every `interval`, the response is reassembled from ISO-TP frames
  (flow control, sequence check, `0x78` response pending) and decoded by sensor lambdas.

Planned: DBC decoding of broadcast frames, MDF4 logging.

Requests go out one at a time, the canbus needs `mode: NORMAL` (not `LISTENONLY`). Only 11-bit
IDs for now.

== Configuration

[source,yaml]
----
external_components:
  - source: github://randybb/esphome-components
    components: [can_tools]

canbus:
  - platform: esp32_can
    id: car_can
    tx_pin: GPIO16
    rx_pin: GPIO17
    can_id: 0x7DF
    bit_rate: 500KBPS

can_tools:
  id: car
  requests:
    - id: engine_rpm
      can_id: 0x7DF        # OBD-II functional address, answered from 0x7E8
      data: [0x01, 0x0C]   # service 01, PID 0C
      interval: 1s
    - id: meter_fuel
      can_id: 0x7C0        # Toyota combination meter, answered from 0x7C8
      data: [0x21, 0x29]
      interval: 60s
      on_response:
        - logger.log:
            format: "fuel raw %u"
            args: ["data[2]"]

sensor:
  - platform: can_tools
    request_id: engine_rpm
    name: Engine RPM
    lambda: return (data[2] << 8 | data[3]) / 4.0f;

binary_sensor:
  - platform: can_tools
    request_id: engine_rpm
    name: Engine running
    lambda: return data[2] || data[3];
----

`data` in the lambdas and `on_response` is the payload of the positive response, response SID
first: for `01 0C` it is `41 0C A B`. A lambda returns `{}` to skip publishing.

[cols="1,1,3",options="header"]
|===
|Option |Default |Description
|`canbus_id` | |The canbus component
|`update_interval` |`100ms` |Scheduling tick: requests start and time out on it.
`component.suspend` / `component.resume` with the `can_tools` id stop and resume all requests,
e.g. while the car sleeps
|`requests[].can_id` | |Request ID
|`requests[].response_can_id` |`can_id` + 8, `0x7E8` for `0x7DF` |Response ID
|`requests[].data` | |Service and its parameters, 1 to 7 bytes
|`requests[].interval` |`5s` |
|`requests[].timeout` |`500ms` |Restarted by a `7F xx 78` response pending
|`requests[].on_response` | |Automation with `data`
|===

Negative responses (`7F`) are logged as a warning, timeouts on debug, frames on verbose.

Based on https://github.com/esphome/esphome/pull/7994[esphome#7994] (`obd`, by @abstractionnl).
