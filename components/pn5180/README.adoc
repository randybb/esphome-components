= pn5180

NXP PN5180 tag reader on SPI. Reads ISO 15693 (NFC-V, NFC Forum Type 5) tags,
their whole memory included, and the UID of the common ISO 14443A tags (NTAG
stickers, MIFARE cards and fobs), so it also serves as a general tag reader for
Home Assistant (`homeassistant.tag_scanned` in `on_tag`).

Decoding is left to the components that listen to the reader:
link:../openprinttag/[openprinttag] for OpenPrintTag filament spool tags.

Every `update_interval` the reader runs an ISO 15693 inventory and, when no
ISO 15693 tag answers, an ISO 14443A activation (WUPA, anticollision, select,
HALT); 4 and 7 byte UIDs, which is what NTAG and MIFARE have. Of an ISO 14443A
tag only the UID is read. One tag at a time: with an ISO 15693 tag in the field,
ISO 14443A tags are not looked for.

A new tag fires `on_tag` with its UID; of an ISO 15693 tag the memory (from the
capability container up to the size it tells) is then read once and handed to
the listening components. When the tag goes away `on_tag_removed` fires.

Nothing blocks the main loop: a frame is sent and the answer is picked up in
`loop()`, which runs only while a tag is expected to answer. With `irq_pin` the
loop sleeps until the PN5180 raises IRQ; without it, it polls the IRQ status
register over SPI while waiting.

== Wiring

The usual PN5180 module needs both 5 V (RF driver) and 3.3 V (logic). The RF
field stays on all the time.

[cols="1,3",options="header"]
|===
|PN5180 |ESP
|NSS |`cs_pin`
|MOSI, MISO, SCK |`spi` bus
|BUSY |`busy_pin`
|RST |`reset_pin` (optional, recommended)
|IRQ |`irq_pin` (optional, recommended)
|REQ |leave open, high at reset starts the firmware download mode
|AUX, GPIO |leave open
|===

== Configuration

[source,yaml]
----
external_components:
  - source: github://randybb/esphome-components
    components: [pn5180]

spi:
  clk_pin: GPIO12
  mosi_pin: GPIO11
  miso_pin: GPIO13

pn5180:
  id: reader
  cs_pin: GPIO10
  busy_pin: GPIO9
  reset_pin: GPIO8
  irq_pin: GPIO14
  on_tag:
    - homeassistant.tag_scanned: !lambda return x;

text_sensor:
  - platform: pn5180
    name: Tag UID
----

[cols="1,1,3",options="header"]
|===
|Option |Default |Description
|`cs_pin` |required |NSS
|`busy_pin` |required |BUSY, every command waits for it to go low
|`reset_pin` | |RST, pulsed on boot
|`irq_pin` | |IRQ, wakes the loop when a tag answered; polarity is read from the chip's EEPROM
|`update_interval` |`1s` |How often the field is polled for a tag
|`data_rate` |`4MHz` |SPI clock, the chip takes up to 7 MHz
|`on_tag` | |New tag in the field, `x` is the UID (`E0-04-...` for ISO 15693 as printed on the tag, `04-A2-...` for ISO 14443A)
|`on_tag_removed` | |Tag left the field, `x` is its UID
|===

`text_sensor` with `platform: pn5180`: the UID of the tag on the reader, empty
without one.

== For decoding components

A component decoding tags implements `pn5180::TagListener` and registers with
`add_listener()`:

* `on_tag(uid)`: a new tag of any kind
* `on_type5_memory(uid, memory)`: the memory of an ISO 15693 tag, again after every write
* `on_tag_removed(uid)`

`write(uid, offset, data)` writes bytes at an offset of that memory; only the
blocks that change are written, then the tag is read again, so the listeners get
what really is on it.

== Firmware

The firmware version is logged on boot (`Firmware 3.5`, `4.1`, ...). Cheap
modules often ship 3.x; ISO 15693 reading works with it. NXP updates the
firmware over the same SPI with REQ held high at reset, the images come with
the NXP NFC Cockpit under NXP's license, so they are not part of this component.

== Range

The common PN5180 modules have a small antenna and reach a few cm, which is fine
for holding a tag to the reader. The OpenPrintTag reader spec asks for a 75 mm
round antenna and 1 W of RF power to read a tag anywhere on a mounted spool.
